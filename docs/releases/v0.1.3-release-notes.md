# MT5 Agent v0.1.3 — draft release notes

**Draft, not published.** Phase 4D is LIVE CI ACCEPTED / GO for the
[Pipeline #11 candidate](../evidence/v0.1.3/phase4d-live-ci-acceptance.md).
Promotion, final tag provenance and publication remain separately approved.
Do not infer a release date from a commit or pipeline timestamp.

## Changes

- Production Windows Agent/control plane runs in Session 0 and uses authenticated
  local named-pipe IPC to a persistent interactive Runtime Worker. The Worker
  owns the serialized MT5 API connection and terminal in its runtime session.
- The Agent stays alive with meaningful degraded health when the Worker is absent.
- Safe production reads include symbols total, terminal version and account
  information; account values are withheld from logs/evidence. No trading is added.
- Agent packaging excludes MetaTrader5, NumPy, legacy direct MT5 adapter,
  interactive Worker module and local terminal inspection. Worker dependencies
  remain separately provisioned and pinned.
- Linux source/unit, Windows no-MT5 build/control, and Windows MT5 integration
  validate one candidate per pipeline, with recursive archive exclusion and
  matching build/control/runtime/package receipts; no post-smoke rebuild.
- Local protocol/capability, durable-state, command lifecycle, transport, security
  and update foundations remain subject to their documented integration/acceptance
  scope; source presence does not make them active production features.

## Known limitations and release conditions

- Approximately 10h30m MT5-host clock skew requires approved remediation and
  revalidation or explicit release-owner risk acceptance before publication.
- CI uses the explicitly approved Liara package mirror; top-level requirements
  are pinned, transitive build dependencies are not fully hash-locked.
- Signed installer, managed Windows Service lifecycle/recovery, customer
  provisioning, supported upgrade/rollback and broader commercial security/
  operations acceptance remain future work. Autologon is a lab bootstrap with
  documented privileged-host risks.
- Kafka/mTLS, durable-command integration and trading are not accepted active
  production features in this candidate. No release gate performs a trade.
- Preserve exact package/receipts before artifact expiry; never rebuild to recover
  an expired accepted artifact.
