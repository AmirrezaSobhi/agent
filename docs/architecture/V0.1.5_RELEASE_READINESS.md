# MT5Agent v0.1.5 Release Readiness

**Status: PARTIAL — the Windows 10 integration runner passed a clean post-boot 15-minute Agent/Worker/MT5 health soak, but the manually installed artifact still has a verified health-reporting defect. Its source fix passed Windows tests but has no replacement artifact because the configured package mirror repeatedly timed out in CI.** Pipeline success does not prove correct installation or stable runtime behavior. This is an internal candidate assessment, not release approval.

## Architecture and lifecycle

```mermaid
flowchart LR
  subgraph S0[Windows Session 0]
    SCM[Windows SCM / LocalSystem] --> Host[.NET Service Host]
    Host --> Agent[Python Agent]
    Agent --> Mgmt[Management Named Pipe]
    Agent --> Runtime[Runtime Pipe / DACL: LocalSystem]
  end
  subgraph Interactive[Session 1 / standard MT5RuntimeUser]
    UI[WPF Desktop] -->|read-only requests| Mgmt
    Worker[Python MT5 Worker] --> MT5[Existing MetaTrader 5]
  end
  Runtime -->|authenticated, v1| Worker
```

The Service starts the Agent in Session 0. The Management pipe serves only the
configured callers and read-only operations. The Worker and existing MT5
terminal run under the standard interactive runtime account. Runtime settings
are machine-local; the Worker pipe authorizes the actual LocalSystem Service
identity. No MT5 installation, profile, account or credential is managed by the
Installer.

## Release decision

The candidate is **not release-ready**. Pipeline #84 is the verified installed
build. After the operator powered the VMs on, the Service and Agent ran in
Session 0 alongside the existing Worker and MT5 terminal in Session 1; the
fresh 15-minute post-boot soak passed 32/32 samples. The earlier controlled
Service restart also preserved Worker and terminal PIDs. The earlier reconnect
transition remains recorded. The current artifact still omits the authenticated
Worker session number from Management health. The source fix is committed, but
Pipelines #85–#87 did not produce a new Installer because the configured
package mirror was unreachable. Restore that mirror, run the unchanged quality gates,
verify a fresh artifact and install that exact artifact before accepting the
health fix operationally. Then repeat the 15-minute soak with the fixed binary.
Keep Windows 11, Windows Server, RDP/logoff, WPF-on-runner and public signing
gates open until real evidence exists.
