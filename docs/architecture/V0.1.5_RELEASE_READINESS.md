# MT5Agent v0.1.5 Release Readiness

**Status: PARTIAL — live Worker/MT5 integration is established on Windows 10, but the currently installed artifact has a verified health-reporting defect and the integrated stability run has observed a reconnect transition.** Pipeline success does not prove correct installation or stable runtime behavior. This is an internal candidate assessment, not release approval.

## Architecture and lifecycle

```mermaid
flowchart LR
  subgraph S0[Windows Session 0]
    SCM[Windows SCM / LocalSystem] --> Host[.NET Service Host]
    Host --> Agent[Python Agent]
    Agent --> Mgmt[Management Named Pipe]
    Agent --> Runtime[Runtime Pipe / DACL: LocalSystem]
  end
  subgraph Interactive[Session 1 / standard MT5RuntimeUser]
    UI[WPF Desktop] -->|read-only requests| Mgmt
    Worker[Python MT5 Worker] --> MT5[Existing MetaTrader 5]
  end
  Runtime -->|authenticated, v1| Worker
```

The Service starts the Agent in Session 0. The Management pipe serves only the
configured callers and read-only operations. The Worker and existing MT5
terminal run under the standard interactive runtime account. Runtime settings
are machine-local; the Worker pipe authorizes the actual LocalSystem Service
identity. No MT5 installation, profile, account or credential is managed by the
Installer.

## Release decision

The candidate is **not release-ready**. Pipeline #84 is a verified build, and
the installed Service can communicate with the existing interactive Worker
when its control identity is configured correctly. The current artifact does
not report the Worker session number in Management health, and the integrated
soak observed a transient disconnect/reconnect sequence. The working-tree fix
for the health field must pass CI, be packaged and installed from a newly
verified artifact, and then pass a fresh 15-minute Agent/Worker/MT5 observation.
Keep Windows 11, Windows Server, RDP/logoff and public signing gates open until
real evidence exists.
