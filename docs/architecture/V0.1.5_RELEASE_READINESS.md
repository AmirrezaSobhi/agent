# MT5Agent v0.1.5 Release Readiness

**Status: PARTIAL — real Windows installation and core Service/Management/WPF checks passed; Worker/MT5 integration is not configured.** This is an internal candidate assessment, not release approval. A green CI pipeline is separate evidence from behavior observed on Windows.

## Architecture and lifecycle

```mermaid
flowchart LR
  subgraph S0[Windows Session 0]
    SCM[Windows SCM] --> Host[.NET Service Host]
    Host --> Agent[Python Agent]
    Agent --> Mgmt[Management Named Pipe]
    Agent --> Runtime[Private Runtime Named Pipe]
  end
  subgraph Interactive[Authorized Windows session]
    UI[WPF Desktop] -->|read-only requests| Mgmt
    Worker[Python MT5 Worker] --> MT5[Existing MT5]
  end
  Runtime --> Worker
```

The Service starts the Agent in Session 0. The WPF client uses a separate,
read-only Management pipe. The Worker and existing MT5 terminal must run in a
configured interactive user session. The Installer does not redistribute or
modify MT5.

## Recovery contract

The installer configures the Service Control Manager to restart after 5 and
15 seconds, with a 24-hour reset period and non-crash failures enabled. The
Windows 10 SCM returned `FAILURE_ACTIONS_ON_NONCRASH_FAILURES: TRUE`, which is
accepted and verified. The Pipeline #82 Agent shutdown event allowed the
Service to stop the Agent cleanly during the explicit Service lifecycle test.

## Release decision

The candidate is **not release-ready** while Worker/MT5 runtime provisioning is
absent and stability metrics remain pending. The next safe step is to provision
the dedicated non-administrator runtime principal and matching MT5 profile
through the documented secure local workflow, then validate the Worker and
safe-read MT5 health without changing trading accounts or placing orders.
After the soak result is recorded, reassess the release gates. Windows 11 and
Windows Server must remain unverified until tested on those operating systems;
the unsigned internal artifact must not be distributed publicly.
